基于 `Ton-yi/globalcart` 仓库 `mixi` 分支的 `81ba678dce491093fff73c08415724c79b7f420f` 提交。修改提交到 `mixi`，供原开发者审查和对接；未部署到原系统。

交互预览：https://globalcart-shipping-detail-preview.itsuchabeautifulday.chatgpt.site/ （示例数据；预览站点的访问权限与 GitHub 仓库独立。）

## 已完成的 UI 修改

- `shipped` / `delivered` 显示“发货日”与 `shipped_date`。字段缺失时显示“未记录”，不拿计划日期代替；其余状态沿用原有计划发货日的显示条件。
- 国际运输方式按 `ShippingMethod.code` 匹配 `pool.shipping_method`，兼容实体 `id` / 历史 `name`；直接展示配置的 `name`，不调用 `t()`，并加 `translate="no"`。找不到配置时保留原始值或自取/暂存的原有回退。配置读取包含已停用方式，便于显示历史申请。
- 收货地址恢复可见，默认折叠。摘要为“发货目的地 = 可选标签 · 收件人 · 收件国家”；描述为 11px 浅色普通字，比 12px 标题更小、更淡。展开后隐藏整个描述，收起后恢复；未填标签不生成占位或多余分隔符。
- 复制按钮使用小号线条图标，展开按钮为 `←` / `↓`。默认无边框、透明背景，悬停时才显示浅色背景和文字反馈，不突出原地址框。
- 地址详情恢复紧凑的纯值单列，不显示字段名前缀，不另做白色卡片或边框。只展示有值的快照字段，默认背景透明，与外框背景相同；值的文字仍可读。每个值可点击复制，悬停、按下及复制成功时变色。原字段名保留为代码映射和无障碍标签，方便对接。全部复制排除地址标签，以换行拼接；邮编有值时额外显示。
- 地址簿 `AddressManagerCard` 的标签改为选填；本次涉及的创建地址入口不再自动填写“新地址”。
- 管理员已发货/已签收面板保留状态摘要，状态徽章左侧增加 ✏️，展开同一套原有的发货信息表单。
- 管理员面板中的运单号成为日本邮政链接，用 `encodeURIComponent` 编码，`target="_blank" rel="noopener noreferrer"` 打开。

## 核对结果：字段和语言

`shipped_date` **已经存在**于 `base44/entities/ShippingPool.jsonc`，不是待新增字段；`AdminShippingInfoPanel` 的确认发货及跳过付款发货处理也会写入它。旧申请可能无值，需要决定是否回填。

`ShippingMethod` 有实体 `id`、业务 `code`、用户配置 `name`。创建申请的选择项以 `m.code` 为值、`m.name` 为文字，通常保存的是 `code`。这个详情页原本只用 `METHOD_LABELS`（目前只有自取、暂存）回退，所以会直接显示 `air` 等值。

本项目的多语言是 `src/lib/i18n.js` 的 `t(中文文案, locale)` 字典，支持 `zh` / `ja` / `en`；`preferred_locale` 保存在本地，切换语言会刷新页面。没有发现对此详情组件进行全局自动文字替换的代码。运输方式的配置名称作为业务数据直接输出，不进入该翻译过程。

地址标签在地址簿 UI 原来是必填，本次已改为选填。详情标签通过申请创建者的地址簿、`final_address_id` 或严格匹配的地址字段读取；没有 ID 时还核对快照中已有的城市、省份、电话、邮编，只有唯一匹配才显示标签。无匹配、匹配不唯一、无标签或无权读取时不显示。显示详细地址只用申请自身的快照，不从地址簿回填缺失值，以免改变历史收货地址。

需要开发者核对：

- 部分创建流程（例如 `base44/functions/createShippingPool/entry.ts`）只写入收件人及地址行，未完整写入 `recipient_phone`、`city`、`state` 等已有快照字段；`ShippingPool.jsx` 的旧创建路径也未复制电话。
- `final_address_id` 不总是写入单独发货申请。如果希望标签永久固定，应在创建时保存可选标签快照，并同步到数据模型；本次没有擅自新增模型字段或覆盖历史数据。
- 不要因为这次 UI 要求而修改已经发货的收货地址。
